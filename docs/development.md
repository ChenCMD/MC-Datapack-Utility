# 開発とリファクタリング

目的は、既存機能の入出力を確認でき、AI が変更箇所と検証方法を判断できる状態にすることです。テストが通る範囲と、まだ動作を保証できない範囲を分けて記録します。

## 機能と検証範囲

| 機能 | 入口と主な処理 | 現在の自動検証 | 未検証の範囲 |
| --- | --- | --- | --- |
| データパック作成 | `src/commands/createDatapackTemplate/`。質問・テンプレート選択、ファイルとフォルダの生成、外部データ取得 | VS Code 上のコマンド登録 | ウィザード、キャンセル、既存ファイルへの追加、通信失敗 |
| ファイル作成 | `src/commands/createFile/`。種類判定、名前入力、テンプレート変数の展開、書き込み | VS Code 上のコマンド登録 | 実際の生成、重複名、途中キャンセル、書き込み失敗 |
| スコア式変換 | `src/commands/scoreOperation/`。空白で区切った式を解析し scoreboard コマンドへ変換 | 出力の固定、整数コマンドの結果検証、単独の core、入力依存の差し替え、実エディターの選択範囲置換 | Minecraft 内での実行、任意の式、カスタム演算子、複雑な条件・不正な関数入力 |
| リソースパスコピー | `src/commands/copyResourcePath/` と `src/utils/common.ts`。pack.mcmeta とファイル種類から名前空間付きパスを生成 | サンプル function の実クリップボードへのコピー | 他のリソース種類、全 pack_format、データパック外の入力 |
| 複数行生成 | `src/commands/multiLineGenerator/`。文字列・連番・式などの置換とエディター編集 | minify 済みバンドルの式置換 | UI、複数選択、他の置換、異常な式 |
| mcfunction 整形 | `src/languages/McfunctionFormatter.ts`。コメント構造の字下げ、任意のリソースパスヘッダー挿入 | LF/CRLF・タブ・空行・コメント階層・ヘッダーの出力固定、core の単独ロード、実 VS Code の編集適用と再整形 | 任意の構文、全 pack_format、同時編集中の動作 |
| 言語・起動 | `src/locales/`、`src/extension.ts` | 4 言語のバンドル内ロード、実 VS Code の起動と5コマンド登録 | 全文言、設定変更中の振る舞い、通信失敗 |

## スコア変換の境界

`core/formula.ts` はトークン列を式の木へ変換します。`core/queue.ts` は式の木をキューへ変換し、必要に応じて objective の入力を要求します。`core/converter.ts` はキューから定数初期化・演算コマンドを生成します。VS Code のコマンドと設定を維持し、変数ごとの objective の回答は変換1回を単位に Map で保持します。条件式と分岐の内部変換でも同じ Map を使い、次のコマンド実行には持ち越しません。

`core/ports.ts` の `locale`、`requestObjective`、`warn` を呼び出し側から渡します。VS Code の入力・ロギングとの接続は `utils/ports.ts`、選択範囲の読み書きとエラー表示は `main.ts` に残します。core は VS Code、拡張機能初期化、ネットワーク、ファイルに依存せず読み込めます。ただしトークン配列やキューを変更する処理は残っており、完全な不変・純粋関数への書き換えではありません。

`tests/fixtures/score-operation.json` は分離前の実装から取得した出力を出発点にしています。数値定数名と条件式の比較対象は、以下の不具合修正に合わせて期待値を更新しました。代入、優先順位、括弧、複合代入、単項負号、16進数、条件式、スケール、設定名変更を含みます。アダプターと core の両方が同じ出力を保つか検証します。期待値を自動再生成する運用にはしません。バグを修正するときは入力と期待する意味を明記し、該当ケースの期待値を意図的に変更します。

## フォーマッターの境界と検証

`src/languages/core/formatter.ts` はドキュメントの行と字下げ・改行・ヘッダーの設定から、行単位の編集計画を生成します。VS Code、ローカライズ、拡張機能初期化、ファイル読み込みに依存しません。`McfunctionFormatter.ts` は TextDocument の行を取り出し、必要な場合にだけデータパックとリソースパスを調べ、編集計画を TextEdit へ変換します。

`tests/fixtures/formatter.json` は分離前の出力を出発点とし、ヘッダー挿入の不具合修正に合わせて期待値を更新しています。20種類の入力について3回整形しても同じ出力になることを、core・アダプター・実 VS Code の統合テストで確認します。先頭の空行、字下げ付きヘッダー、CRLF、空の function、本文中のリソースマーカーも含みます。

ヘッダー挿入は、リソースパスが解決できて、先頭の空行を除いた最初の内容行に同じヘッダーがない場合だけ行います。判定時はヘッダーの前後のスペース・タブも許容します。新しくヘッダーを追加するときは、先頭に空行がなければ本文との区切りを1行追加します。既存ヘッダーがある場合やデータパック外では、ヘッダー用の空行を追加しません。既存の先頭空行と本文中の `#>` コメントは保持し、過去に生成済みの重複ヘッダーを一括削除する処理は行いません。単独の CR は従来の StringReader と同じ扱いを保ちますが、任意の混在改行への対応は保証していません。

## 修正済みのスコア変換の問題

- `0x10`、`016`、`16.0` などは、実際の値に正規化した `$MCDUtil_16` を初期化し、演算でも同じスコアを参照します。同じ値の初期化は重複させません。
- 単純な条件式では、左右の値を代入した一時スコアと、比較に使う一時スコアが一致します。6種類の比較で真・偽の両分岐を検証します。
- 同じ変数の objective の回答は、条件式や分岐を含む変換全体で再利用します。ユーザーの変数から値をコピーした一時スコアは、設定した内部処理用 objective に統一します。
- objective の入力を途中でキャンセルした場合は、後続の入力を要求せず変換結果を返しません。条件式・then・else の内部変換でのキャンセルも全体へ伝えます。

`scripts/score-results.test.mjs` は生成したコマンドを、小さなテスト用実行器 `tests/helpers/scoreboard.cjs` で評価し、実際の整数値が期待どおりになるかを確認します。この実行器は set・代入・加減乗算・単純比較に限定し、未初期化スコアの参照や未対応コマンドは失敗にします。Minecraft サーバーの代替ではなく、小数・整数範囲・除算・複合条件などの挙動は保証しません。

## 既知の問題と未保証の動作

以下は現状維持のためテストに残している挙動であり、推奨仕様ではありません。

- `- 2 + 3` は通常期待する `(-2) + 3` ではなく `0 - (2 + 3)` の処理順になります。
- `valueScale` は代入先にも適用され、通常の代入先の名前を維持することを保証しません。

複合条件、ネストした条件式、カスタム prefix と条件式の組み合わせは未保証です。関数引数の欠落など、不正入力で解析が終了するかも未保証です。従来の引数区切りループには終了条件の見直しが必要です。`rpnCalculate` は現在どのコマンドからも呼ばれておらず、文字列の演算子認識とゼロ結果の扱いは未検証です。複数行生成には直接 `eval` が残っています。`jsonKeyWalker.ts` の filter は未実装です。これらは個別の不具合修正として、失敗を再現するテストから着手します。

## 確認方法

```bash
pnpm install --frozen-lockfile
pnpm check
xvfb-run -a pnpm test:integration
VSCODE_TEST_VERSION=1.75.0 xvfb-run -a pnpm test:integration
pnpm package --out /tmp/mc-datapack-utility.vsix
```

デスクトップ環境では `xvfb-run -a` を外せます。Linux の仮想画面には Xvfb と xauth、Electron のシステムライブラリが必要です。Dev Container の Dockerfile に含めています。統合テストは VS Code 本体をダウンロードし、fixture を一時ディレクトリへコピーして独立したプロファイルで実行します。編集したドキュメントは保存せず、クリップボードは終了時に復元します。拡張機能の起動処理は従来どおり外部バージョン情報を非同期に取得しますが、テストの期待値はその応答を使いません。

`pnpm check` は画面・VS Code ダウンロードが不要な確認です。Check CI と Release CI はこれに加えて実 VS Code の統合テストを実行し、失敗時は後続のパッケージ作成・公開に進みません。統合テストの既定は stable です。CI では stable と最小バージョン 1.75.0 の両方を確認します。

## 続ける順序

1. 既知のスコア変換不具合を、意味を確認する個別テストとともに修正する。単なる出力一致から、Minecraft で実行できる結果の確認へ進める。
2. フォーマッターの出力固定・責務分離・ヘッダー挿入時の再整形の修正は完了。今後の変更でも、既存本文の保持と再整形で出力が変わらないことを検証する。
3. パス判定・テンプレート変数・置換処理を単独テストできるようにし、ファイル生成は一時ディレクトリと失敗する書き込みを使って検証する。
4. データパック作成の通信と UI を差し替え可能にし、既存ファイル保護・キャンセルを検証する。最新 Minecraft のフォルダ構成対応は、互換性変更として明示する。

機能追加・改修では、該当行の未検証範囲を一つずつ減らし、その記録と `AGENTS.md` の導線を更新します。
