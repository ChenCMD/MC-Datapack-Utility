## データパック作成の境界と検証

`src/commands/createDatapackTemplate/core/command.ts` は生成用ノードの選択、名前空間・テンプレート・追加質問、外部データ取得、変数展開、順次生成と完了通知を担当します。`core/ports.ts` に入力・進捗・通信・URI 操作・保存・ローカライズ・エラー通知を定義し、`main.ts` が従来の API を接続します。Create/Add のディレクトリ選択、再選択、pack.mcmeta の読み取り、完了ダイアログは既存の `nodes/` に残し、生成ノードとして差し替えます。core は VS Code、拡張機能初期化、ローカライズのロードや utility barrel に依存しません。JSON の追加処理は既存の `jsonKeyWalker` をアダプターから渡し、core へその依存を持ち込みません。

`scripts/datapack-wizard.test.mjs` は分離前の8ケースで内容と順序を固定し、分離後はアダプターと core に同じ期待値を適用します。CRLF テキスト、JSON の字下げ、パスと変数、生成と追加、既存ファイル保持、テキスト・JSON の追加、明示した create/add の選択、質問の重複除外、外部取得成功と失敗、入力キャンセル、保存失敗時の継続を確認します。`scripts/datapack-wizard-results.test.mjs` は全件成功・部分失敗・全件失敗、既存ファイルの保持、追加失敗、pack.mcmeta とフォルダーの保存失敗を検証します。`tests/fixtures/datapack-templates.json` は分離前のデフォルトテンプレートのラベル・生成先・ダウンロードパスを固定し、pack_format 7/9/10/48 の境界を比較します。実 VS Code では core に保存ヘルパーと一時ワークスペースを接続し、生成内容、既存ファイル保持、テンプレート選択のキャンセルで保存しないことを確認します。読み取り専用の実ファイルシステムプロバイダーで全件失敗と部分失敗を再現し、通常の完了通知を抑え、保存できた内容を保持することも確認します。ダイアログを操作する end-to-end テストではありません。`main.ts` の実 UI・通信・設定との接続は統合テストの対象外です。

外部取得が失敗するとファイル生成全体へ進みません。個別項目の生成失敗は通知後に次の項目へ進み、全件成功時だけ完了通知とフォルダーを開く確認を表示します。失敗があり、ファイルの保存または既存ファイルの保持が成功していれば部分失敗の警告を表示します。全ファイルが失敗した場合は、暗黙の data フォルダーが作成できても失敗のエラーを表示します。ファイルを含まないフォルダーだけの処理ではフォルダーの成功数で判定します。core の `GenerationResult` はファイル件数・成功したファイルとフォルダーの件数・失敗件数を集計します。途中まで生成したファイルの削除やロールバックはありません。既存ファイルは append 指定がなければ保持し、存在確認と保存は別操作です。カスタムテンプレートは選択肢の作成時にラベル・JSON・追加内容を含めて複製し、変数展開では実行ごとのコピーだけを変更します。同じ設定を再利用しても前回の入力値を持ち越しません。`core/templates.ts` は JSON の列挙可能な own key を複製し、`__proto__` や `constructor` も通常の JSON キーとして保持します。外部取得のパス変換コールバックは同じ関数参照を維持します。`scripts/datapack-wizard-config.test.mjs` で異なる名前空間・追加質問・日付・生成先を使った2回の実行、元の設定の保持、配列・null・`__proto__` を含む JSON と追加内容、選択しなかったテンプレートの保持、質問の重複除外とコールバックを確認します。実 VS Code でも同じ設定で名前空間・日付を変えて JSON を2回保存し、元の設定が保持されることを確認します。実ダイアログの操作、保存と追加の原子性、実通信の失敗形態は未保証です。

生成先は変数展開後に `core/paths.ts` で検証し、URI の結合・字下げ設定やリソースパスの取得・存在確認・読み取り・保存の前に拒否します。生成・追加・フォルダー・外部取得の返却項目を同じ規則で扱います。`/` 区切りの相対パスだけを許可し、空または空白だけの成分、`.`・`..`、バックスラッシュ、コロン、制御文字（C0・C1）と行・段落区切り文字、成分末尾の半角スペースとドットを拒否します。フォルダーの末尾の `/` は1つまで許可し、ファイルでは許可しません。日本語・空白を含む名前とドットファイルは保持し、Minecraft のリソース名制約は一般のテンプレートパスには適用しません。無効な項目はローカライズされたエラーと失敗件数に含め、残りの有効な項目の生成を続けます。`scripts/datapack-wizard-paths.test.mjs` は変数・追加質問・外部取得からの不正パスと保存前の拒否を検証し、実 VS Code ではデータパック外の既存ファイルを追加処理から保持し、外へのファイルとフォルダーの作成を拒否することを確認します。検証は生成ノードが返したルートに対する字句的な相対パス検証であり、ノードが選択するルートやデータパック名自体の検証ではありません。OS 間で同じパス規則にするため、Linux/macOS でも末尾がドットの成分を許可しません。名前空間の入力欄は従来の文字種検証を維持しているため、`v1.`・`.`・`..`・空の成分を含む名前空間などは入力できても、その値を生成先に使う項目が生成時に拒否されます。外部取得が選ばれた場合、生成先の検証は取得後です。既存のシンボリックリンク・ジャンクションの解決、OS 固有の予約名、プロバイダー固有のパス解釈や同時操作まで保証しません。

`scripts/datapack-wizard-dialogs.test.mjs` は Create/Add の実ノード、`vscodeWrapper` の入力・警告・完了通知、メッセージ ID と入力検証を接続し、VS Code API・URI 操作・データパック探索・ファイル読み取り・ローカライズと未使用の数値検証ヘルパーを差し替えます。Error は実装から読み込んだ共通クラス参照を各バンドルへ渡します。フォルダー選択のオプション、データパック内での作成確認と再選択、重複名の確認と名前変更、入力のキャンセル、既存メタデータの読み取り、作成後のフォルダーを開く選択を確認します。ディレクトリ選択の実ノードから発生した `UserCancelledError` が core でも無通知で終了し、その後の入力・生成へ進まないことも確認します。実 UI のクリック操作や、探索・読み取りヘルパー自身の動作を検証するテストではありません。名前入力では `.`・`..` の拒否と、空文字・区切り文字の拒否を確認します。日本語・空白・ドットを含む通常の名前では、選択したディレクトリの直下が作成先になることを確認します。

Create の名前検証は空文字と `\/:*?"<>|`、名前全体が `.`・`..` になる入力を拒否し、選択したディレクトリの直下になる URI を返します。日本語・空白・ドットを含む通常の名前は保持します。OS の予約名、`...` などドットだけの名前や末尾のドット・スペースをプロバイダーが再解釈する場合、シンボリックリンクの解決は未保証です。pack_format は `parseInt` により `2abc` を2、`1.5` を1として受け付けます。Add は pack_format が number かどうかだけを確認し、0・負数・小数も返します。`max_format` のみの形式や配列形式は受け付けません。メタデータの読み取り失敗・不正 JSON・pack_format の欠落や不正な型は同じローカライズされたエラーになります。description は不正 JSON や欠落・null で空文字へ戻りますが、文字列以外の値もそのまま返し、読み取り失敗やルートが JSON の null である場合の TypeError は伝播します。これらの残る数値入力・メタデータの問題は正常仕様として推奨するものではなく、将来の個別修正に向けた再現ケースです。

## スコア変換の境界

`core/formula.ts` はトークン列を式の木へ変換します。`core/queue.ts` は式の木をキューへ変換し、必要に応じて objective の入力を要求します。`core/converter.ts` はキューから定数初期化・演算コマンドを生成します。VS Code のコマンドと設定を維持し、変数ごとの objective の回答は変換1回を単位に Map で保持します。条件式と分岐の内部変換でも同じ Map を使い、次のコマンド実行には持ち越しません。

`core/ports.ts` の `locale`、`requestObjective`、`warn` を呼び出し側から渡します。VS Code の入力・ロギングとの接続は `utils/ports.ts`、選択範囲の読み書きとエラー表示は `main.ts` に残します。core は VS Code、拡張機能初期化、ネットワーク、ファイルに依存せず読み込めます。ただしトークン配列やキューを変更する処理は残っており、完全な不変・純粋関数への書き換えではありません。

`tests/fixtures/score-operation.json` は分離前の実装から取得した出力を出発点にしています。数値定数名と条件式の比較対象は、以下の不具合修正に合わせて期待値を更新しました。代入、優先順位、括弧、複合代入、単項負号、16進数、条件式、スケール、設定名変更を含みます。アダプターと core の両方が同じ出力を保つか検証します。期待値を自動再生成する運用にはしません。バグを修正するときは入力と期待する意味を明記し、該当ケースの期待値を意図的に変更します。

## フォーマッターの境界と検証

`src/languages/core/formatter.ts` はドキュメントの行と字下げ・改行・ヘッダーの設定から、行単位の編集計画を生成します。VS Code、ローカライズ、拡張機能初期化、ファイル読み込みに依存しません。`McfunctionFormatter.ts` は TextDocument の行を取り出し、必要な場合にだけデータパックとリソースパスを調べ、編集計画を TextEdit へ変換します。

`tests/fixtures/formatter.json` は分離前の出力を出発点とし、ヘッダー挿入の不具合修正に合わせて期待値を更新しています。20種類の入力について3回整形しても同じ出力になることを、core・アダプター・実 VS Code の統合テストで確認します。先頭の空行、字下げ付きヘッダー、CRLF、空の function、本文中のリソースマーカーも含みます。

ヘッダー挿入は、リソースパスが解決できて、先頭の空行を除いた最初の内容行に同じヘッダーがない場合だけ行います。判定時はヘッダーの前後のスペース・タブも許容します。新しくヘッダーを追加するときは、先頭に空行がなければ本文との区切りを1行追加します。既存ヘッダーがある場合やデータパック外では、ヘッダー用の空行を追加しません。既存の先頭空行と本文中の `#>` コメントは保持し、過去に生成済みの重複ヘッダーを一括削除する処理は行いません。単独の CR は従来の StringReader と同じ扱いを保ちますが、任意の混在改行への対応は保証していません。

## リソースパスとテンプレートの境界

`src/core/datapack/fileTypes.ts` は相対パスと pack_format からファイル種類・フォルダ名を求めます。形式不一致の通知は `createFileTypeResolver` のコールバックへ返し、`src/types/FileTypes.ts` が従来の警告表示と URI の相対パス変換を担当します。メタデータと通常の種類判定は維持しています。テンプレート用の `migrateFilePath` は移行元のフォルダを形式に依存せず判定し、指定した pack_format のフォルダへ変換します。名前空間・入れ子のパス・拡張子・末尾のスラッシュは保持し、フォルダだけのパスも変換します。対象形式にその種類が存在しなければ `undefined` を返し、テンプレートの生成対象から除外します。移行では形式不一致を警告せず、通常の種類判定では従来どおり警告します。`src/core/datapack/resourcePaths.ts` は相対パス文字列から名前空間とリソースパスを計算し、`src/utils/common.ts` は既存の URI 引数を受けるアダプターです。ファイル読み込み、データパックの探索、日付の取得は今回移していません。

`tests/fixtures/resource-paths.json` は分離前の16種類の出力を出発点にし、形式不一致の function パス2件の移行結果だけを意図した修正に合わせて更新しています。旧・新フォルダ、タグ、入れ子の worldgen、未知のディレクトリ、データパック外、ドットファイル、Windows 型の区切り文字を含みます。core とアダプターの同じ結果、pack_format 43/45 前後の既存の判定、形式不一致通知を検証します。これは既存コードの互換性確認であり、全 Minecraft バージョンの仕様を保証するものではありません。実 VS Code では一時ワークスペースに7種類のパスを生成してコピー結果を確認します。Windows/macOS 実機の検証はしていません。

`src/core/templates/variables.ts` は文字列・配列・JSON の変数展開です。`src/types/Variables.ts` は既存の import を保つ再エクスポートです。未知の変数、大小文字の違い、リテラル値、非再帰的な展開、配列・JSON・スカラーを単独で検証します。従来どおり、文字列配列は新しい配列を返し、JSON オブジェクトはその場で変更します。展開対象の JSON は必要に応じて呼び出し側で複製してください。

`scripts/resource-migration.test.mjs` は core とアダプターの両方で、既存メタデータの14種類のフォルダ変更と pack_format 43/45・worldgen 9/10 の境界、逆方向の移行、フォルダ・ファイル・未対応の種類と警告の扱いを確認します。Minecraft 1.18.2 の pack_format は[公式リリースノート](https://feedback.minecraft.net/hc/en-us/articles/4531177623437-Minecraft-Java-Edition-1-18-2)に従い9へ訂正し、`worldgen/configured_structure_feature` を9まで維持します。10から `worldgen/structure` に移行し、9のテンプレートが除外されないことと通常の種類判定・フォルダ取得も確認します。これはパス変換の検証であり、データパック作成ウィザード全体の検証ではありません。移行は `/` 区切りの相対パスを対象とし、Windows 型の区切り文字は従来どおり変更しません。

リソースパス計算では、未知の種類にワイルドカードによる変換が残り、`.nbt` は変換対象ではありません。これらはテストで再現し、別の挙動修正として扱います。JSON 内部の `null` による変数展開の例外は修正済みです。オブジェクト・配列の任意の深さにある `null` は保持し、文字列の変数だけを展開します。オブジェクトのその場での変更と配列の新規作成は維持し、回帰テストで確認します。ファイル生成の検証範囲は次節に記録します。

## ファイル生成の境界と検証

`src/commands/createFile/core/command.ts` は名前入力・変数の準備・テンプレート展開・保存・ファイルを開く順序を担当します。`core/ports.ts` に URI の操作、設定・日付・ファイル情報、入力・確認・保存・エラー表示を定義し、`main.ts` が従来の VS Code API と接続します。core は VS Code や拡張機能初期化に依存せず読み込めます。接続する関数はコマンド呼び出し時に解決し、既存の循環 import の初期化順序を持ち込みません。カーソル位置は core では行・文字位置、アダプターでは Range に変換します。

分離前のコマンドで生成成功・重複名・キャンセル・保存失敗などをテストに固定し、分離後の同じ挙動を確認しました。Node の一時ディレクトリで内容と既存ファイルの保持を確認し、保存失敗時は開く処理へ進まずエラーを通知することを検証します。`scripts/file-storage.test.mjs` は実装済みの保存ヘルパーと実ファイルを接続し、UTF-8 のバイト列、既存ファイル拒否、プロバイダーの保存失敗を確認します。

実 VS Code の統合テストでは、core と本番の保存ヘルパーをテスト用にバンドルし、名前入力・確認・日付・メタデータなどをテスト用のポートに差し替え、保存とエディター表示は実 API を使います。実ワークスペースへの保存・保存内容・エディター表示・カーソル位置・重複名・キャンセルを確認し、読み取り専用のテスト用ファイルシステムで保存拒否も検証します。入力ダイアログを自動操作する end-to-end テストではありません。テスト用バンドルは `out/integration/` に生成し、VSIX に含めません。

今回の変更は責務分離と検証の追加です。既存の確認と保存は別操作であり、並行した作成への原子的な上書き防止は保証しません。また、保存ヘルパーの存在確認は stat の失敗を不在として扱います。入力名は小文字英数字・ドット・アンダースコア・ハイフン・スラッシュによる相対パスに限定し、末尾以外の空のパス成分、絶対パス、`.`・`..` の成分を拒否します。末尾の名前は空にでき、空入力で選択フォルダー内の `.mcfunction`・`.json`、`bar/` で `bar/.mcfunction`・`bar/.json` を生成します。`foo:bar/` のような無名リソースを維持し、拡張子追加後の実ファイルで重複を確認します。既存のサブフォルダー内のファイル名は指定できます。入力検証で拒否された名前は保存とエディター表示へ進まないことを回帰テストで確認します。シンボリックリンクの解決や OS 固有の予約名まで検証する処理は含みません。カーソル位置は展開後の内容から計算します。大小文字を問わず `%cursor%` マーカーを除去し、変数内の改行と UTF-16 の文字位置を反映します。マーカーが複数ある場合は従来どおり最後のマーカー付きテンプレート行の最初の位置を使います。変数の値として挿入されたマーカー風の文字列は再展開しません。既知の変数と英数字・アンダースコア・ドット・ハイフンによる未知の変数トークンを優先し、変数の終端の `%` はマーカーの開始と共用しません。ファイル作成では `50% %fileName%` のような単独の `%` の後にある変数も展開します。この修正はファイル作成のテンプレートに限定し、データパック作成側の既存展開処理は変更しません。単独テストと実 VS Code の内容・カーソル位置で確認します。ファイル保存後に開く処理が失敗した場合は、保存済みのファイルを消す処理はありません。

## ProjectTSB の互換性確認

`tests/fixtures/projecttsb/compatibility.json` は [TheSkyBlessing](https://github.com/ProjectTSB/TheSkyBlessing/tree/7ecb161fc41bc1fa52a73da0597fc5f17cfe6f0e) と [Asset](https://github.com/ProjectTSB/Asset/tree/f97883b94a16bf97a84934b17c6f76c0810d260b) の固定コミットから、代表的なリソース名と MC Datapack Utility の設定を取得した CC0 の fixture です。`.mcfunction`・`.json` の拡張子だけを持つファイルと、数字・ドット・ハイフン・深い階層を含む名前を保持します。これはリソース ID の末尾 `/` をファイルシステム上の末尾 `/` として保存する処理ではありません。入力名に拡張子を追加した実ファイルのパスを検証します。

`scripts/projecttsb-compatibility.test.mjs` は代表パスの種類・入力名・コピー用 ID、両プロジェクトの function テンプレートと無名リソースのヘッダー、整形の繰り返しを確認します。Asset の84個のカスタムテンプレートを、異なるリソース名で2回実行し、既存タグへの追加、JSON、function ヘッダー、設定の保持を検証します。Asset はウィザードの `%namespace%` を固定の `asset` 名前空間内のリソース名として使っており、`nested/0002.compat` のような入れ子もテストします。この入力を単純に Minecraft の名前空間文字種だけへ狭めないでください。テンプレートが質問していない未知の変数は従来どおり残します。

オンラインの全パス確認は `node scripts/audit-projecttsb.mjs` で明示的に実行します。各パックの pack.mcmeta、両プロジェクトの設定とライセンス、全件数と代表パスを固定コミットのソースから再計算し、fixture と比較します。fixture の入力を意図的に更新するときだけ `node scripts/audit-projecttsb.mjs --refresh-fixture` を使い、差分をレビューしてください。通常の `pnpm check` はネットワークを使わない固定 fixture を検証します。固定コミットでは TheSkyBlessing の2,116件、Asset の16,925件の JSON/function パスについて、作成名・ウィザードの生成先・種類判定を確認しました。リポジトリのソースや設定は変更しません。実 VS Code でもプロジェクトと同じ function テンプレートで無名ファイルを保存し、カーソル、重複保護、クリップボードの末尾 `/` を確認します。

TheSkyBlessing が使う `tags/damage_type` と Asset が使う `trim_pattern` を種類表と作成テンプレート設定に追加しました。damage type タグは [1.19.4 の仕様](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-19-4)の形式12以降、trim pattern は [23w04a の実験機能](https://www.minecraft.net/en-us/article/minecraft-snapshot-23w04a)の形式11以降をパス判定の対象にします。ゲーム内の実験フラグは判定しません。複数行生成のタグ選択リストは変更せず、今回の damage type タグ対応はファイル作成とパスコピーを対象にします。既存のタグ置換には種類 ID をフォルダー名として扱う問題があり、別の修正対象です。未知の種類で使うワイルドカードをこれらの種類へ適用しないため、damage type タグは `minecraft:bypasses_cooldown` のような正しい ID をコピーします。

この確認は拡張機能のファイル作成・テンプレート生成・パス変換・整形についてのものです。Minecraft サーバー上の実行、他の拡張機能、全カスタム質問への任意の回答、構造ファイルの作成、最新の外部コミットとの互換性までは保証しません。親フォルダーの作成可否は保存ポートとプロバイダーの挙動に依存します。

## 修正済みのスコア変換の問題

- 演算子と比較演算子は表自身に登録されたプロパティだけを認識します。`toString`・`constructor`・`__proto__` などの名前も通常の score holder として代入先・演算の値・条件式の左右に使用できます。未登録の名前を演算子位置に指定した場合は従来のローカライズされたエラーを返し、同名で明示的に登録されたカスタム演算子は認識します。コマンドとテストは `core/operateTable.ts` で表を作成し、カスタムの `__proto__` もプロトタイプを変更せず登録します。`scripts/score-names.test.mjs` で生成コマンドの整数値とエラー、実 VS Code で `constructor = toString + 1` の選択範囲置換を確認します。

- `if(` の返り値を参照するときは `valueScale` を再適用しません。比較の左右と各分岐の通常の値には引き続き倍率を適用します。倍率10で `a = if( b > 1 , 2 , 3 )` は20または30となり、定数・変数・分岐内の加減算・後続の演算・単項負号・複合代入・並列した2つの条件式を結果で確認します。倍率1と0も確認し、実 VS Code の選択範囲置換に倍率付き条件式を追加しています。

- カスタム関数の引数は解析した式の木として展開先へ挿入し、1つの括弧付きの項として優先順位を保持します。同じプレースホルダーを複数回使っても引数を解析するのは1回です。引数の各値と展開先に直接記述した定数には `valueScale` を適用し、挿入済みの式には再適用しません。`scripts/score-custom-functions.test.mjs` で複数項・括弧・単項符号・入れ子のカスタム関数・繰り返した引数・条件式の引数と分岐の整数結果を確認し、実 VS Code では `product( 2 + 3 , 4 )` の倍率1と10を確認します。複雑な条件式の保証は引き続き下記の範囲に限定します。

- 関数引数は入れ子の括弧・関数を数え、外側のカンマだけで分割します。定義された引数の個数と一致しない入力を拒否し、`if( ( b > 1 ) )` の引数不足で停止しない問題を修正しました。通常の条件式、括弧付きの分岐、カスタム関数の単純な引数と0引数を確認します。0引数関数の括弧内の空白は引数として数えません。

- `valueScale` は右辺の各項に適用し、代入先の score holder と objective は保持します。通常代入と複合代入、括弧で囲んだ単一の代入先を確認し、数値・符号付きの名前・計算式を代入先に指定した場合は拒否します。scale fixture の期待値は、この意図した修正に合わせて更新しました。

- 単項の `+`・`-` は直後の値・括弧式・関数にだけ結合します。`- 2 + 3` は `(-2) + 3` として評価し、符号の連続や演算子の右側の負号も扱います。括弧と関数は対応する閉じ括弧までを1項として読み、後続の演算には通常の優先順位と演算子表の結合方向を適用します。連続した減算や、負数の乗算に複数の加算が続く式も結果で確認します。整数の生成コマンドの結果と意図的に更新した unary minus fixture で確認します。

- `0x10`、`016`、`16.0` などは、実際の値に正規化した `$MCDUtil_16` を初期化し、演算でも同じスコアを参照します。同じ値の初期化は重複させません。
- 単純な条件式では、左右の値を代入した一時スコアと、比較に使う一時スコアが一致します。6種類の比較で真・偽の両分岐を検証します。
- 同じ変数の objective の回答は、条件式や分岐を含む変換全体で再利用します。ユーザーの変数から値をコピーした一時スコアは、設定した内部処理用 objective に統一します。
- objective の入力を途中でキャンセルした場合は、後続の入力を要求せず変換結果を返しません。条件式・then・else の内部変換でのキャンセルも全体へ伝えます。

`scripts/score-results.test.mjs` は生成したコマンドを、小さなテスト用実行器 `tests/helpers/scoreboard.cjs` で評価し、実際の整数値が期待どおりになるかを確認します。この実行器は set・代入・加減乗算・非負整数の除算と剰余・単純比較に限定し、未初期化スコアの参照や未対応コマンドは失敗にします。Minecraft サーバーの代替ではなく、小数・整数範囲・負数の除算と剰余・複合条件などの挙動は保証しません。

## 既知の問題と未保証の動作

以下は今回の修正で残している既知の挙動であり、推奨仕様ではありません。

複合条件、ネストした条件式、カスタム prefix と条件式の組み合わせは未保証です。関数引数の分割は有限の走査に変更し、引数不足・余分な引数・空の引数・閉じ括弧の不一致を拒否します。同期解析が無限ループすると通常のテストタイムアウトでは停止できないため、回帰テストは子プロセスに期限を設けます。任意の不正入力や極端に深い式は未保証です。`rpnCalculate` は現在どのコマンドからも呼ばれておらず、文字列の演算子認識とゼロ結果の扱いは未検証です。複数行生成には直接 `eval` が残っています。`jsonKeyWalker.ts` の filter は未実装です。これらは個別の不具合修正として、失敗を再現するテストから着手します。

## 確認方法

```bash
pnpm install --frozen-lockfile
pnpm check
xvfb-run -a pnpm test:integration
VSCODE_TEST_VERSION=1.75.0 xvfb-run -a pnpm test:integration
pnpm package --out /tmp/mc-datapack-utility.vsix
```

デスクトップ環境では `xvfb-run -a` を外せます。Linux の仮想画面には Xvfb と xauth、Electron のシステムライブラリが必要です。Dev Container の Dockerfile に含めています。統合テストは VS Code 本体をダウンロードし、fixture を一時ディレクトリへコピーして独立したプロファイルで実行します。編集したドキュメントは保存せず、クリップボードは終了時に復元します。拡張機能の起動処理は従来どおり外部バージョン情報を非同期に取得しますが、テストの期待値はその応答を使いません。

`pnpm check` は画面・VS Code ダウンロードが不要な確認です。Check CI と Release CI はこれに加えて実 VS Code の統合テストを実行し、失敗時は後続のパッケージ作成・公開に進みません。統合テストの既定は stable です。CI では stable と最小バージョン 1.75.0 の両方を確認します。

## 続ける順序

1. 既知のスコア変換不具合を、意味を確認する個別テストとともに修正する。単なる出力一致から、Minecraft で実行できる結果の確認へ進める。
2. フォーマッターの出力固定・責務分離・ヘッダー挿入時の再整形の修正は完了。今後の変更でも、既存本文の保持と再整形で出力が変わらないことを検証する。
3. リソースパス判定・テンプレート変数展開とファイル生成の責務分離・主要な検証は完了。保存の原子性などの未保証範囲は、個別の挙動修正として扱う。
4. データパック作成の通信・UI・保存の境界と主要な検証は追加済み。保存・追加の原子性や実通信の失敗形態などの残る挙動は個別に修正する。最新 Minecraft のフォルダ構成対応は、互換性変更として明示する。

機能追加・改修では、該当行の未検証範囲を一つずつ減らし、その記録と `AGENTS.md` の導線を更新します。
